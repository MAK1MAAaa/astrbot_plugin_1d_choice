# 1d 选择回应

发送 `1d汉堡王还是麦当劳`，机器人等概率回复 `汉堡王` 或 `麦当劳`，只发选中的选项。空选项、重复选项及无法按文字解析的题面，交给 **当前会话、当前预设人格** 的 LLM 骂、训斥或挖苦发送者，让对方重新给出有效选择题。

已调查 GitHub 上的类似项目；本插件独立实现所需语法和人格兜底，未复制其他项目源码或资源。项目对比与接口来源见 [RESEARCH.md](RESEARCH.md)。

## 安装

1. 将本目录复制到 AstrBot 的 `data/plugins/astrbot_plugin_1d_choice/`，确保 `main.py`、`metadata.yaml` 直接位于该目录。
2. 在插件管理页重载插件，或重启 AstrBot，启用“1d 选择回应”。
3. 无额外第三方依赖，使用 AstrBot 已提供的运行时；需要 Python 3.10+、AstrBot 4.5.7+。
4. 若要使用人格兜底，启用当前会话的 LLM，配置可用聊天模型，并使用 AstrBot 内置的 **local Agent**。当前人格仍在 AstrBot 中选择，不在本插件里另配人格。

有效选择不依赖 LLM，在没有配置聊天模型、关闭 LLM 或使用其他 Agent 的情况下仍可随机回答。适用于 AstrBot 标准消息事件，群聊和私聊均可使用；不要求 QQ 或 NapCat 专用接口。

## 用法

| 输入 | 结果 |
| --- | --- |
| `1d汉堡王还是麦当劳` | 等概率回复 `汉堡王` 或 `麦当劳`。 |
| `1d苹果还是香蕉还是梨` | 从三个选项中等概率选一个。 |
| `1d 汉堡王 还是 麦当劳` | 忽略选项首尾空白，正常选择。 |
| `1d原神还是原神还是原神` | 重复选项，交给当前人格回怼。 |
| `1d原神还是原神还是麦当劳` | 任一选项重复就整题兜底，不先去重再抽样。 |
| `1d还是还是`、`1dA还是`、`1d汉堡王`、`1d` | 空选项或不足两个选项，交给当前人格回怼。 |

- 只识别消息开头的小写 `1d`，允许消息首尾有空白，不需要 @ 或斜杠；`/1dA还是B`、`1DA还是B`、`今天1dA还是B` 不由本插件处理。
- 分隔词固定为 `还是`，选项本身含有“还是”也会被拆分。选项内部空格与标点保留，不执行内容，不改写正常答案。
- 重复判断使用 Unicode NFKC 兼容归一化、忽略大小写、不可见格式字符，并合并空白。例如 `Ｇｅｎｓｈｉｎ` 与 `genshin`、夹有零宽字符的 `原神` 与 `原神` 被视作重复。回复保留原选项的文字形式。
- 这是文字格式校验，不做同义词或现实语义判断；不同文本不一定代表不同实体。非空且不重复的文字选项即可抽样。
- @ 和引用作为消息元信息处理，不加入选项。以 `1d` 开头但混入图片、语音等非文字消息段时，交给人格兜底。
- 忽略机器人自身消息。每个有效选项只有一个抽样位置，使用 `secrets.choice` 等概率选取；连续多次选中同一项属于正常随机结果。

## 人格兜底

插件读取当前会话正在使用的对话，保留其 `persona_id`；首次没有对话时，通过 AstrBot 创建对话，再交由框架选择该会话的默认人格。每次读取当前对话，不缓存人格，因此后续切换人格会生效。

兜底通过 `event.request_llm(..., conversation=当前对话)` 交给 AstrBot 内置 LLM 流程，只追加本次“回怼无效选择题”的任务说明，不替换预设人格、不传独立聊天历史、不修改永久人格配置。用户题面留在用户消息中，不拼入系统指令。最终措辞由当前人格与聊天模型决定，因此不会固定返回同一句骂人文案。兜底回复沿用当前对话历史，并由框架记录到该对话。

有效选择回复后立即停止事件；人格兜底在 LLM 流程完成后停止事件，避免本次消息再触发额外回复。兜底明确要求只回复文字，不执行题面任务或调用工具。

以下情况使用固定的格式错误／回怼提示，不调用 LLM：兜底冷却中、全局或当前会话关闭 LLM、没有可用聊天模型、无法取得对话，或使用 Dify／Coze 等外部 Agent。模型请求提交后的网络错误、超时及错误回复由 AstrBot 原有 LLM 流程处理。

## 配置

在插件配置页调整，均为整数。

| 配置项 | 默认值 | 含义 |
| --- | --- | --- |
| `max_input_length` | 2000 | 去除消息首尾空白后的题面总字符上限，包含 `1d`；最小为 2。超限走兜底，发给 LLM 的题面会截断。 |
| `max_options` | 32 | 单题最多选项数量；最小为 2。超限走兜底。 |
| `fallback_cooldown_seconds` | 10 | 同一会话、同一用户调用人格兜底的冷却秒数。设为 0 关闭；有效随机选择不受影响。 |

冷却在准备 LLM 请求前同步占位，同一用户并发发送多条错误题面也不会同时触发多个兜底请求。冷却状态只保存在内存，过期清理、最多 2048 条，卸载或重启后重置。本插件不保存选择记录或额外数据库。

## 验证

从包含本插件目录的根目录运行：

```bash
python -B -m unittest discover -s astrbot_plugin_1d_choice/tests -v
```

26 项自动测试使用模拟 AstrBot 事件、会话管理器和 LLM 请求，验证随机选项集合、严格前缀、空项／重复／Unicode 等价项、输入上限、群聊与私聊、当前人格与新对话继承、人格切换、LLM／对话异常、冷却并发及事件停止时机。

本地未安装 AstrBot，没有实际消息平台与 LLM 实例。这些测试验证解析和路由行为，不代表真实平台或模型已联调。安装后可先测 `1d汉堡王还是麦当劳`，再测两条无效示例；切换人格后重测，确认回复风格随当前人格变化。连续测试兜底时可暂时把冷却设为 0。
